
# Web 1.0
The content is published on the web with the principal aim of being “humanreadable”.
Standard HTML is focused on ___how___ to represent the content. 
There is no notion of ___what___ is represented.

Few tags (e.g. \<title\>) provide an implicit semantics but …
- … their content is not structured.
- … their use is not really standardized

The problem: ==it is not possible to automatically reason about the data== automatically.

# Semantic Web

The goal of semantic web is to solve this problem. How? By extending the current web with knowledge about the content (semantic information).
The Semantic Web is about two things:
- It is about common formats for integration and combination of data.
- It is also about language for recording how the data relates to real world objects.

Principles SW would like to preserve: 
- Globality 
- Informaton distribution 
- Information inconsistency 
	- Content inconsistency 
	- Link inconsistency 
- Information incompleteness 
	- … of contents 
	- … of routing information (links)

Adding information is not enough 
- Information should be structured (e.g., Linneo classification for the living world) 
	- Ontologies!!!! 
- There is the need of some inference mechanism (e.g., syllogism, FOL, DL) 
	- Logic!!!! (and DL in particular) 
- We should be able to infer new knowledge 
	- We need the proofs that originated such new knowledge

# Semantic Web Tools

### URI
Semantic Web exploit URIs to define _uniquely identified_ concepts. 

### XML
Created for supporting _data exchange_ between _heterogeneous_ systems (hardware and software. It is _human-readable_ and _machine-readable_. 

### Resource Description Framework (RDF/RDFS)
It's a Standard W3C, XML-based language for _representing “knowledge”_.
- Based on the concept of triple:
- <subject, predicate, object>
- <resource, attribute, value>

#### Graph representation
- A node for the subject 
- A node for the object 
- A labeled arc for the predicate
![[rdf_example.png]]

# RDF – Expressive Power
- RDF supports: 
	- _Types_ (classes) by means of the attribute type (that assume as value an URI) 
	- _Subject/object_ of a sentence can be also collections (bag, sequence, alternative) 
	- _Meta-sentences_, through reification of the sentences (“Marco says that Federico is the author of web page xy”)
RDFS allows to describe classes and relations with other classes/resources 
- type 
- subClassOf 
- subPropertyOf 
- range 
- domain

RDF is very similar with E/R models in DBMS, but RDF is more expressive. 

## RDFa
RDFa is a specification for attributes to express structured data in _XHTML_. 
The rendered, hypertext content of XHTML is reused by the RDFa markup. 

### SPARQL
SPARQL can be used to express _queries_ across diverse data sources, whether the data is stored natively as RDF or viewed as RDF via middleware. 
It is a mix of SQL and PROLOG. 
![[sparql_example.png]]

### Ontology Web Language (OWL 1.0)
This is another Standard W3C, and it is based upon/extend RDF/RDFS. 


# Knowledge Graphs
The Semantic Web stack seems too complex, and not so fast for the Google needs. Reasoning on the [[6. Description Logics#Boxes in Semantic Web | T-Box]] is computationally expensive, and might even not terminate

How does Google allow us to search and answer questions? 
- Create a common, _simple vocabulary_… schema.org 
- Create a _simple_, but _robust corpus of types, properties_, etc. 
- Push the web to adopts these standards (well, after all it is Google!)

Basic idea: _just store the information in terms of nodes and arcs connecting the nodes_. 
FOL is thrown in the bin. 
…==T-Box and A-Box are stored at the same "level"==. 
- Billions of _factual knowledge_, in form of "_triplettes_" 
- _No reasoning_: ==every consequence possible is calculated and stored, in order to save time==. Reasoning (for this reason T-Box and A-Boxes are stored in the same level). 
	- There are only assertions. 
- Graph algorithms used to fast traverse the graph, looking for the solution 
- No conceptual schema: data from various sources, with different semantics can be mixed freely (avoids the knowledge acquisition bottleneck) 

## Evaluating the quality of a Knowledge Graph
3 key concepts:
- _Coverage_ Does the graph have all the required information? If not, can we estimate how much of it? (Usually the answer to the former question is NO…) 

- _Correctness_ Is the information correct? 
	- Correctness… it depends on the type of information (it can be objective or subjective), and it depends on the intended use of the information 

- _Freshness_ Is the content up-to-date? 
	- Keep in mind the change rate of the domain: it is different to represent stock quotes, and parenthood

## Graph embedding
We can apply ML tecnhiques to knowledge graphs. 
One of this tecnhiques  that lets us do just that is graph embedding. 

Triplettes come in the shape of (h, r, t)
-  h (head) and t (tail) are entities
-  r is a relation
- a Knowledge Graph is a set S={(h, r, t)}

IDEA: let us represent _entities_ and _relations_ into a _vectorial space_.
- Would it be possible then to _learn_ the relation function?
	- Input: (h,t) and r
	- Output: a ANN able to predict _r_, given some h and t.
-  Would it be possible to predict some entity?
	-  Input: (h, r) and t
	-  Output: a ANN able to predict _t_, given some h and r.

Usually, three steps: 
1. Choose a representation space for entities and relations 
2. Choose a scoring function 
3. Learn a representation function
