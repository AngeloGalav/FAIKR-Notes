In Prolog predicates (i.e., programs) and terms (i.e., data) have the same syntactical structure. As a consequence, predicates and terms can be exchanged and exploited in different roles!!!

There are several pre-defined predicates that allows to deal with these structures, and work with them. 

# The `call` predicate

If terms are predicates, I could “prepare/create” a term in a ”proper” way … and then… EXECUTE IT!

`call(T)`: the _term T_ is considered as a atom (a _predicate_), and the Prolog interpreter is requested to evaluate (_execute_) it.
Obviously, at the moment of the evaluation, T must be a non-numeric term. 
==The predicate `call` takes as input a term that can be interpreted as a predicate==.

```
p(a). 
q(X):- p(X). :- call(q(Y)).

:- call(q(Y)).
yes Y = a
```

==The predicate call can be used also within programs==.

# The `fail` predicate
`fail` takes no arguments (its arity is zero). ==Its evaluation always fails==!
- As a consequence, it forces the interpreter to _explore other alternatives_… 
- … in other words, __it explicitly activates the backtracking__

We can use this to implement the [[13. Prolog#NAF (Negation As Failure) and SLDNF|negation as failure]]:
```
not(P) :- call(P), !, fail.
not(P).
```
not(P) is true if P is not a consequence of the program (meaning that there aren't any possible rule to choose for P). 
If not(P) is not true, then the program executes the command `fail`. The rule "`not(P).`" will then be executed, and `not(P)` will return true. 
Otherwise, if P is true, `call(P)` succeeds and will be called, and the cut (`!`) point will not be reached (rule `not(P).` will still be eventually reached at some point though).
