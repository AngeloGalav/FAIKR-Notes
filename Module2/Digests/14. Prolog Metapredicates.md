In Prolog predicates (i.e., programs) and terms (i.e., data) have the same syntactical structure. As a consequence, predicates and terms can be exchanged and exploited in different roles!!!

There are several pre-defined predicates that allows to deal with these structures, and work with them. 

# The `call` predicate

If terms are predicates, I could “prepare/create” a term in a ”proper” way … and then… EXECUTE IT!

`call(T)`: the _term T_ is considered as a atom (a _predicate_), and the Prolog interpreter is requested to evaluate (_execute_) it.
Obviously, at the moment of the evaluation, T must be a non-numeric term. 
==The predicate `call` takes as input a term that can be interpreted as a predicate==.

```
p(a). 
q(X):- p(X). :- call(q(Y)).

:- call(q(Y)).
yes Y = a
```

==The predicate call can be used also within programs==.

# The `fail` predicate
`fail` takes no arguments (its arity is zero). ==Its evaluation always fails==!
- As a consequence, it forces the interpreter to _explore other alternatives_… 
- … in other words, __it explicitly activates the backtracking__

We can use this to implement the [[13. Prolog#NAF (Negation As Failure) and SLDNF|negation as failure]]:
```
not(P) :- call(P), !, fail.
not(P).
```
not(P) is true if P is not a consequence of the program (meaning that there aren't any possible rule to choose for P). 
If not(P) is not true, then the program executes the command call(P) successfully, then will execute the cut (`!`) and then the `fail`. We've succeeded in proving `P`, so the not(P) is not true. 
Otherwise, call(P) fails, I will not reach the cut (`!`) point, and instead will backtrack to the set of definition and execute the rule "`not(P).`".  So, `true` will be returned. 

## Combining `fail` and `cut`
Initially, fail and cut together were often used as a way to deal with default values/reasoning for a given program, or ho define _exceptions_, i.e.

This program is true for all the birds except penguins and ostrich…
If I pass to the program the name of a penguin, then it will fail. 
This approach is not really that optimized, since before getting to the default value, we have to check all the exceptions first. 

# Predicates `setof` and `bagof`
In Prolog, the usual query `:- p(X).` is interpreted with X existentially quantified. As result, it is returned a possible substitution for variables of p such that the query is satisfied.
Sometimes, it might be interested to answer to queries like "which is the set S of element X such that p(X) is true?" (second-order query)

- `setof(X,P,S).` 
S is the _set_ (no repeats) of instances X that satisfy the goal P 

- `bagof(X,P,L).` 
L is the _list_ (with repeats) of instances X that satisfy the goal P

In both cases, if there are no X satisfying P, the predicates fail.

`findall(X, P, S) `

- If there is no X satisfying P, then findall returns an empty list

# Verifying properties of terms 
- `var(Term)`: true if Term is currently a variable 
- `nonvar(Term)`: true if Term currently is not a free variable 
- `number(Term)`: true if Term is a number 
- `ground(Term)`: ==true if Term holds no free variables==.

# Accessing the clauses of a program
- `clause(Head, Body)`: true if (Head, Body) is unified with a clause stored within the database program.

When evaluated:
- Head must be instantiated to a non-numeric term 
- Body can be a variable or a term describing the body of a clause 

Its evaluation opens choice points, if more clauses with the same head are available.
