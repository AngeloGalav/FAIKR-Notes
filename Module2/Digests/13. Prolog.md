# Terminology

A Prolog program is a set of definite clauses of the form: 
- Fact A. 
- Rule A :- B1, B2,…, Bn. 
- Goal :- B1, B2,…, Bn.

Where A and Bi atomic formulas: 
- `A` head of the clause 
- `B1,B2,…,Bn` body of the clause 
- Symbol `,` is for conjunction 
- Symbol “:-” stands for the _logical implication_, where A is the consequent, and B1,B2,…,Bn is the antecedent. (B1,B2,…,Bn -> A)

An Atomic formula has the form:
```
p(t1, t2, ..., tn)
```
Where: 
- $p$ is a predicate symbol (alphanumeric string starting with low-capital letter) 
- $t_1,t_2, …,t_n$ are terms

- A _term_ is recursively defined as:
	- Costants (integer/floating numbers, alphanumeric strings starting with a _low-capital letter_) 
	- Variables (alphanumeric strings starting with a capital letter or starting with the symbol "\_")
	- `f(t1, t2, ..., tk)` is a term if "$f$" is a function symbol with k arguments $t_1, t_2, ..., t_k$ are terms.
		- Constants can be viewed as functions with zero arguments (arity zero).

## Declarative interpretation
Variables within a clause are universally quantified:
- For each fact: `p(t1, t2, ..., tm)`, If `X1,X2,…,Xn` are the variables appearing in `t1,t2,…,tm` the intended meaning is: $$
∀X1, ∀X2,…, ∀Xn .\ (p(t1,t2,…,tm))$$
For each rule: `A :- B1,B2,…,Bk` 
- If `Y1,Y2,…,Yo` are the variables appearing in the body only (-> exist clause)
- If `X1,X2,…,Xn` are the variables appearing in both the body and the head

# SLD Resolution

It aims to determine a substitution for the variables in the goal, for which the goal logically follows from the program.

The resolution adopted by LP is the SLD that has two possible _non-determinisms_: 
- The rule of computation 
- The search strategy

In Prolog we have:
- __Rule of computation__: 
	- Rule "_left-most_";
	- given a "query": `?- G1, G2, ..., Gn`. It is selected the _left-most literal_ (G1). 
- __Search strategy__ 
	- Depth-first with chronological backtracking

# Procedural Interpretation of Prolog 
In Prolog, the definition of a function in given in terms of set of clauses of a program P whose:
- Heads have the same predicate symbol (the name of the funciton)
- Predicate symbols have the same arity (same number of arguments)

- Arguments appearing in the head of the procedure are the _formal parameters_
`:- p(t1,t2,...,tn).`
This can be viewed as the call to procedure `p`. Arguments of `p` (terms `t1,t2,...,tn`) are the __actual parameters__.
- ==Unification then can be viewed as the mechanism for passing the parameters==. 
- There is no distinction between input parameters and output parameters (the returned parameters) (reversibility).
- The body of the clause then can be viewed as a sequence of calls to procedures.
- Two clauses with the same head are two alternative definitions of the body of a procedure (function overloading)
- All the variables are "_single assignment_": they assume a single value along the proof, except when looking for alternative paths in the SLD tree (“backtracking”).

> Predicate_symbol = rule = functions are the same things.

# Arithmetic

In Logic there is not any way to evaluate mathematical functions, since numbers dont have a definition. Integer numbers can instead be represented through the _Peano notation_:
$$s(s(s(...s(0)...)))$$
We would have a function like this when using the Peano notation:
```
prod(X, 0, 0). 
prod(X, s(Y), Z):- prod(X, Y, W), sum(X, W, Z).
```

But obv is not practicable.
In Prolog, _both integers and floating point numbers are atoms_. Math operators are function symbols predefined in the language. Every expression is then a Prolog term.
Binary operators are supported with a pre-fix notation, as well as the in-fix notation.
	- i.e.: +(2,3) and 2+3 are equivalent.

## Predicate _is_
```
T is Expr
```
T can be a numerical atom or a variable,  Expr must be an expression (i.e. mathematical expression).
Expression Expr _is evaluated_ and the result is _unified_ with T. 
==Variables in Expr MUST BE COMPLETELY INSTANTIATED at the moment of evaluation==.

### Relational Operators
```
>, <, >=, =<, ==, =/=
```
They are all supported in Prolog. In the form:
```
Expr1 REL Expr2
```
where REL is a relational operator, and Expr1 and Expr2 are expressions. ==Expr1 and Expr2 are __evaluated__: Mind it! They both have to be __completely instantiated__==.

## Iteration and recursion in Prolog 
In Prolog there is no iteration (no while, for, repeat…). But… you can get iterative behaviour through recursion!!!

- A function $f$ is _tail-recursive_ if $f$ is the "most external call" in the recursive definition (tail recusion makes it no more computationally complex than normal iteration)
- In other terms, if the result of the recursive call is not subject of any other call. 
- Tail-recursion is equivalent to iteration 
	- It can be evaluated in constant space, like in iteration. 
	- However, in Prolog things get complicated: non determinism, choice points…

# LISTS 
In Prolog, lists are terms build upon the special atom "empty list, [ ]" and the constructor operator "`.`"

Recursive definition: 
- the atom `[ ]` represents the empty list 
- the term `.(T, List)` is a list if `T` is any term, and `List` is a list. `T` is named also "head of the list", while `List` is named "tail of the list". 

The following are all lists: 
- `[ ]` 
- `.(a, [])` 
- `.(a, .(b, [ ]))` 
- `.(f(g(X)), .(h(z), .(c, [ ])))` 
- `.([ ], [ ])` 
- `.( .(a,[]), .(b, []))`
Prolog provides a simpler notation for the list constructor: `.(T, List)` can be represented also as `[T | List]`.  So we have:
-  `[ ]` 
- `[a | [] ]` 
- `[a | [b | []]]` 
- `[f(g(X)) | [h(z) | [c | [] ]]]` 
- `[[ ] | [ ]]` 
- `[ [a |[]] | [b | []]]`

Lists like, e.g. `[a | [b | [c|[]]]]` can be written as `[a, b, c]`.

##  Unification and Lists 
The unification algorithm is extended to the lists, and provide a powerful method for accessing their content:
```
p([1, 2, 3, 4, 5, 6, 7, 8, 9]).

:- p(X).
yes X=[1,2,3,4,5,6,7,8,9] 

:- p([X|Y]). 
yes X=1 Y=[2,3,4,5,6,7,8,9] 

:- p([X,Y|Z]). 
yes X=1 Y=2 Z=[3,4,5,6,7,8,9] 

:- p([_|X]). 
yes X=[2,3,4,5,6,7,8,9]
```
