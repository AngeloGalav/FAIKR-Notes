Objects fall into categories (also multiple) which can be more general or specific than others. Since objects may have parts, ==the relationships among an object’s parts _is essential_ to them being considered a member of a category==.

Let’s focus on noun phrases...
We would like to represent:
- individuals 
	- E.g., john, david, maria, ...
- category nouns, aka Concepts
	- Used to describe basic category classes. 
	- E.g., Hunter, Teenager, ...
- relational nouns, AKA Roles 
	- Used to describe objects that are parts or attributes or properties of other objects. E.g., Child, Age, Born, . .

Some ambiguity: in natural language many nouns can be used to refer as _category_ or _as relations_. E.g., child can be used: 
- as a category: a person of a young age 
- to indicate a relation: the inverse of parent

We would like to represent complex concepts as the results of some “composition” of simpler concepts, and to know if an individual belongs to some category or not.

___Description Logic___ is a (family of) logic that focus on the description of the terms.

# Simple DL
Two different sets of symbols: ___logical symbols___ (with a fixed meaning) and ___non-logical symbols___ (domain-dependent). 
![[dl_logical_symbols.png]]
![[non_logical_symbols.png]]

Complex Concepts can be created by combining atomic concepts together, using the ___concept forming operators___ 
- every atomic concept is a concept; 
- if $r$ is a role and $d$ is a concept, then [ALL r d] is a concept;
- if $r$ is a role and $n$ is a positive integer, then [EXISTS n r] is a concept;
- if $r$ is a role and $c$ is a constant, then [FILLS r c] is a concept;
- if $d_1,\dots, d_n$ are concepts, then [AND d1 . . . dn] is a concept.

What about sentences? 
- if d1 and d2 are concepts, then (d1 ⊑ d2) is a sentence; 
- if d1 and d2 are concepts, then (d1 .= d2) is a sentence; 
- if c is a constant and d is a concept, then (c → d) is a sentence;

> [!warning]
>A KB in a description logic like DL is considered to be any collection of sentences of this form.

- constants stand for individuals in some application domain;
- concepts stand for classes or categories of individuals;
- roles stand for binary relations over those individuals.

### Boxes in Semantic Web
In many research area there is a distinction between: 
- A-Box (ABOX -> FACTS), Assertion Box: a list of facts about _individuals_. 
- T-Box (TBOX -> AXIOMS), Terminological box: a list of sentences (also called axioms) that describes the _concepts_.

In the Semantic Web initiative, such distinction is not so stressed. It happens you can have the former, the latter, or more often, a combination of both

# Interpretations
An interpretation $\Im$ is a pair $(D, I)$ where:
-   $D$ is called domain
-   $I$ is a mapping from the **************non-logical symbol************** of $DL$ to elements and relations over $D$.
    1.  for every constant $c,I[c]\in D$
    2.  for every atomic concept $a,I[a]\subseteq D$
    3.  for every role $r, I[r] \subseteq D\times D$

## Interpretation - complex concepts

-   $I[[\text{ALL r d}]]=\{x\in D \vert \text{for any y, if}\langle x,y\rangle\in I[r],\text{then}\ y\in I[d] \}$
-   $I[[\text{EXISTS n r}]]=\{x\in D \vert \text{there are at least n distinct y such that}\langle x,y\rangle\in I[r]\}$
-   $I[[\text{FILLS r c}]]=\{x\in D \vert\langle x,I[c]\rangle\in I[r]\}$
-   $I[[\text{AND}\ d_1\ldots d_n]]=I[d_1]\cap \dots \cap I[d_n]$

Entailment is defined as in First Order Logic:
> [!INFO]
> A set $S$ of sentences logically entails $\alpha$ if for every interpretation $\Im$, if $\Im\models S$ then $\Im\models \alpha$

# Reasoning on the [[#Boxes in Semantic Web|TBOX]]

In description logic the are some fundamental questions that we would like to get an automatic answer to. Given a knowledge base expressed as a set S of sentences:

1.  ***Satisfiability***: A concept $d$ is satisfiable with respect to $S$ if there exists an interpretation $\Im$ of $S$ such that $I[d]$ is nonempty. In such cases, ==$\Im$ is a _model_ of $d$==.
2.  ***Subsumption:*** A concept $d$ is subsumed (sussunto/soprassunto/generalizzato) by a concept $d'$ to $S$ if $I[d]\subseteq I[d']$ for every model $\Im$ of $S$
3.  ***Equivalence:*** Two concepts $d$ and $d'$ are equivalent respect to $S$ if $I[d]= I[d']$ for every model $\Im$ of $S$
4.  ***Disjointness:…***

# Quick Summary
We have two fundamental questions that we would like to get an automatic answer to. Given a knowledge base expressed as a set S of sentences:
1. does a constant c satisfies concept d? 
2. is a concept d subsumed by a concept d ′ ?

Answering to these questions amounts to compute the entailment for the subsumption problem.

# Extending DL
It is possible to extend the presented description logic in several directions: 
- by adding concept-forming operators; 
- by relating roles, and considering also complex roles;
- by adding rules.

## Adding concept-forming operators - AT MOST & ONE-OF
We have already the operator EXISTS. We could similarly add the operator AT-MOST, where \[AT-MOST n r\] describes individuals related by role r to at most n individuals.
![[at_most_example.png]]

It would be nice to specify that a role can be filled only by individuals belonging to a certain set (<u>without recurring to a concept</u>). We could add the operator ONE-OF, where [ONE-OF c1c2 . . . cn] is a concept satisifed only by ci , used in conjunction with ALL would lead to a restriction on the individuals that could fill a certain role.
![[one_of_example.png]]

## Rules 
In the language presented here, there is no way of saying, for example, that all instances of one concept are also instances of another. 

We could this by adding definitions of the type (d1 .= d2), where d1 and d2 are complex concepts with their own definition... but this could lead to several classification problems, when computing subsumption. 

Some description logics allows the introduction of rules, like for example:
- (if d1 then [FILLS r c])
Meaning that every individual of class d1 also has the specified property

# An entire family of logics
Description logics is a family of logics. Each logic is different depending on which operators are admitted in the logic. 
Of course, more operators means:
- higher expressivity; 
- higher computational costs 
- the logic it might result to be undecidable...

A description logic is named upon the operators included. A minimal, yet useful logic is named $AL$: Attributive Language.
