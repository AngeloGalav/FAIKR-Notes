# Terminology

A Prolog program is a set of definite clauses of the form: 
- Fact A. 
- Rule A :- B1, B2,…, Bn. 
- Goal :- B1, B2,…, Bn.

Where A and Bi atomic formulas: 
- `A` head of the clause 
- `B1,B2,…,Bn` body of the clause 
- Symbol `,` is for conjunction 
- Symbol “:-” stands for the _logical implication_, where A is the consequent, and B1,B2,…,Bn is the antecedent. (B1,B2,…,Bn -> A)

An Atomic formula has the form:
```
p(t1, t2, ..., tn)
```
Where: 
- $p$ is a predicate symbol (alphanumeric string starting with low-capital letter) 
- $t_1,t_2, …,t_n$ are terms

- A _term_ is recursively defined as:
	- Costants (integer/floating numbers, alphanumeric strings starting with a _low-capital letter_) 
	- Variables (alphanumeric strings starting with a capital letter or starting with the symbol "\_")
	- `f(t1, t2, ..., tk)` is a term if "$f$" is a function symbol with k arguments $t_1, t_2, ..., t_k$ are terms.
		- Constants can be viewed as functions with zero arguments (arity zero).

∀X1, ∀X2,…, ∀Xn .\ (p(t1,t2,…,tm))$$

# SLD Resolution

It aims to determine a substitution for the variables in the goal, for which the goal logically follows from the program.

The resolution adopted by LP is the SLD that has two possible _non-determinisms_: 
- The rule of computation 
- The search strategy

In Prolog we have:
- __Rule of computation__: 
	- Rule "_left-most_";
	- given a "query": `?- G1, G2, ..., Gn`. It is selected the _left-most literal_ (G1). 
- __Search strategy__ 
	- Depth-first with chronological backtracking

# Procedural Interpretation of Prolog 
In Prolog, the definition of a function in given in terms of set of clauses of a program P whose:
- Heads have the same predicate symbol (the name of the funciton)
- Predicate symbols have the same arity (same number of arguments)

- Arguments appearing in the head of the procedure are the _formal parameters_
`:- p(t1,t2,...,tn).`
This can be viewed as the call to procedure `p`. Arguments of `p` (terms `t1,t2,...,tn`) are the __actual parameters__.
- ==Unification then can be viewed as the mechanism for passing the parameters==. 
- There is no distinction between input parameters and output parameters (the returned parameters) (reversibility).
- The body of the clause then can be viewed as a sequence of calls to procedures.
- Two clauses with the same head are two alternative definitions of the body of a procedure (function overloading)
- All the variables are "_single assignment_": they assume a single value along the proof, except when looking for alternative paths in the SLD tree (“backtracking”).

# Arithmetic

In Logic there is not any way to evaluate mathematical functions, since numbers dont have a definition. Integer numbers can instead be represented through the _Peano notation_:
$$s(s(s(...s(0)...)))$$
We would have a function like this when using the Peano notation:
```
prod(X, 0, 0). 
prod(X, s(Y), Z):- prod(X, Y, W), sum(X, W, Z).
```

But obv is not practicable.
In Prolog, _both integers and floating point numbers are atoms_. Math operators are function symbols predefined in the language. Every expression is then a Prolog term.
Binary operators are supported with a pre-fix notation, as well as the in-fix notation.
	- i.e.: +(2,3) and 2+3 are equivalent.

## Iteration and recursion in Prolog 
In Prolog there is no iteration (no while, for, repeat…). But… you can get iterative behaviour through recursion!!!

- A function $f$ is _tail-recursive_ if $f$ is the "most external call" in the recursive definition (tail recusion makes it no more computationally complex than normal iteration)
- In other terms, if the result of the recursive call is not subject of any other call. 
- Tail-recursion is equivalent to iteration 
	- It can be evaluated in constant space, like in iteration. 
	- However, in Prolog things get complicated: non determinism, choice points…

# LISTS 
In Prolog, lists are terms build upon the special atom "empty list, [ ]" and the constructor operator "`.`"

Recursive definition: 
- the atom `[ ]` represents the empty list 
- the term `.(T, List)` is a list if `T` is any term, and `List` is a list. `T` is named also "head of the list", while `List` is named "tail of the list". 

The following are all lists: 
- `[ ]` 
- `.(a, [])` 
- `.(a, .(b, [ ]))` 
- `.(f(g(X)), .(h(z), .(c, [ ])))` 
- `.([ ], [ ])` 
- `.( .(a,[]), .(b, []))`
Prolog provides a simpler notation for the list constructor: `.(T, List)` can be represented also as `[T | List]`.  So we have:
-  `[ ]` 
- `[a | [] ]` 
- `[a | [b | []]]` 
- `[f(g(X)) | [h(z) | [c | [] ]]]` 
- `[[ ] | [ ]]` 
- `[ [a |[]] | [b | []]]`

Lists like, e.g. `[a | [b | [c|[]]]]` can be written as `[a, b, c]`.

## Unification and Lists 
The unification algorithm is extended to the lists, and provide a powerful method for accessing their content:
```
p([1, 2, 3, 4, 5, 6, 7, 8, 9]).

:- p(X).
yes X=[1,2,3,4,5,6,7,8,9] 

:- p([X|Y]). 
yes X=1 Y=[2,3,4,5,6,7,8,9] 

:- p([X,Y|Z]). 
yes X=1 Y=2 Z=[3,4,5,6,7,8,9] 

:- p([_|X]). 
yes X=[2,3,4,5,6,7,8,9]
```

### The '\_' variable
The '\_' variable is syntactic sugar, which represents a variable that can unify with every value., and that wont be return as a result. It is a sort of a 'catch_all'. 
It tells, essentially, that we are not interested in that value.

# _The CUT operator_ 
It is a very procedural operator, not very much logical. 
There are a number of pre-defined predicates that allows to interfere and control the execution process of a goal. 
The _cut_ "`!`" is among them. It has no logic meaning, no declarative semantics…  but it heavily affects the execution process.

## How CUT works 
The evaluation of the CUT is to make some choices _as definitive and non-backtrackable_. 
In other words, ==some blocks are removed from the __backtracking__ stack==. 
The CUT alters the control of the program… When used, declarativeness is partially lost.

Consider the clause: 
```
p :- q1, q2,…, qi, !, qi+1, qi+2,…, qn.
```

The evaluation of `!` (always) succeeds \[in the sense that, if the resolution process \], and it is ignored in backtracking; 
All the choices made in the evaluation of goals `q1, q2,..., qi` and goal `p` are made definitive; in other words, the choice points are removed form the backtracking stack. 
==Alternative choices related to goals placed after the cut are not touched/modified==. 

If the evaluation of `qi+1, qi+2,…, qn` fails, then the "whole" `p` fails. Even if there were other alternatives for `p`, these would have been removed by the cut.

![[prolog_cut_example.png]]

Let's look at another very quick example:
```
list_member(X,[X|_]) :- !.
list_member(X,[_|TAIL]) :- list_member(X,TAIL).

list_append(A,T,T) :- list_member(A,T), !.
list_append(A,T,[A|T]).
```

 In this case, if member is present in the list, the we'll have, the ==program will stop without trying the other rules==. 

Another example to better understand: 
```Prolog
 filter([], []).
 filter([H|T], [H|Rest]) :- H>0, filter(T, Rest).
 filter([_|T], Rest) :- filter(T, Rest).


filter([], []).
filter([H|T], [H|Rest]) :- H>0, !, filter(T, Rest).
filter([_|T], Rest) :- filter(T, Rest).
```

In the first case, we could have many possible L, since we can decide when H>0 we can decide between the 2° or 3° rule almost arbitrarly. 

This does not happen in the second example, since the evaluation of ! _causes the choice points to be removed entirely_. 


# Negation
Negation is a problem in Prolog. 
In prolog, negation is based on the _closed world assumption_. For this reason, it only allows definite clauses, __no negative literals__.

CWA(P) = {~A | it does not exists a refutation SLD for P$\cup${A} }

So, if we have:
```
capital(rome). 
city(X) :- capital(X).
city(bologna).
```

We can infer `~capital(bologna)`. 

But here's the problem. Let's consider this case:
```
city(rome):- city(rome).
city(bologna).
```
I
Operationally, it happens that if A is not logical consequence of P, _SLD resolution is not guaranteed to terminate_.  In the code above, SLD resolution makes the problem not terminate. 


### NAF (Negation As Failure) and SLDNF
Let's drop the CWA: Prolog adopts a less powerful rule, the _Negation as Failure_.

Given a program P, we name $FF(P)$ <u>the set of atoms for which the proof fails in a finite time</u> 
- NF rule: NF(P)={ ~A | A $\in$ FF(P)} 

So, SLD is extended with NF, giving us _SLDNF_. SLDNF is used in Prolog to implement the Negation as Failure. 
To prove ~A, where A is an atom, the Prolog interpreter tries to prove A 
- ==If the proof for A succeeds==, then the proof of ~A fails 
- If the proof for A fails in a finite time, then ~A is proved successfully

If we try to prove some goal which contains variables, I'm gonna mix in negation as failure with variables quantification, and it will be a mess. 

The problem lies in the meaning of quantifiers of variables appearing in negative literals:
![[negation_example.png]]
![[sldnf_fails_example.png]]
The idea to avoid this to only apply negation on _ground rules_, and when there are not free variables anymore (that is variables without a value).
To do that, we need to have a resolution rule that is safe. For example:
- We select first the predicates which do not have variables, and evaluate the rest later. 
- This rule will break the program made by the developer though. 

>[!WARNING]
>Definition of __ground rules__: they are variables that have been instatiated (so we know their value) all the way into the proof. 
 
### Additional info on SLDNF 
Let $:-L_1,...,L_m$ be the goal, where $L_1,...,L_m$ are literals (atoms or negation of atoms).
A SLDNF step is defined as: 
- __Do not select any negative__ literal $L_i$, _if it is not "ground"_;
- If the selected literal $L_i$ is positive, then apply a normal SLD step 
- If $L_i$ is ~A (with A "ground") and _A fails in finite time_ (it has a finite failure SLD tree), then $L_i$ succeeds, and the new goal to solve is:
$$
:- L_1,...,L_{i-1},L_{i+1},...,L_m
$$

A selection rule is __safe__ if it selects _a negative literal_ only when it is ground. 
The selection of ground negative literals only is needed to ensure correctness and completeness of SLDNF, but Prolog uses a __SLDNF__ implementation is not safe at all!
- ==Prolog does not use a safe selection rule==: it selects ALWAYS the _left-most literal_, without checking if it is ground.
- Indeed, it is a non-correct implementation of SLDNF.
