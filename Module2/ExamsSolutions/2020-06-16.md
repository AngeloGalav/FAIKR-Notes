# Question: 
"The candidate is invited to present the Prolog “vanilla” meta-interpreter, and to
shortly comment (in natural language) the meaning of the clauses"

### Answer:
The code for the vanilla metainterpreter is:
```
solve(true) :- !. 
solve( (A,B) ) :- !, solve(A), solve(B).
solve(A) :- clause(A,B), solve(B).
```
Essentially, it is an interpreter for the language Prolog, written in Prolog. In that sense, it is a predicate that answers _true_ if Goal can be proved using the clauses of the current program. 

A comment for each clause:
1) The first clause allows the interpreter to conclude, in case that the variable can be unified with a fact.  
2) In case a parameter is composed of two atoms. In such cases, the meta interpreter is called on each atom. This rule also implements the left-most SLD resolution, since we are calling the interpreter on the left most term first.  
3) The third clause is maybe the most important one. The `clause` proposition returns true if the term can be unified with a clause store within the db of the program, and if there is, the interpreter is called on the body of the clause. 

# Prolog:
```Prolog
After that, the candidate is invited to write a meta-interpreter solve(Goal,
ListOfSubGoals) that is evaluated to true if Goal can be proved; moreover, in
the parameter ListOfSubGoals the meta interpreter will return the list of the
subgoals used to prove the Goal.
For example, given the program:
p(X) :- q(X), r(X).
p(X) :- s(X).
q(X) :- t(X).
r(1).
r(2).
r(3).
t(1).
t(2).
s(12).
and the query ?- solve(p(X), Result), the following outcomes are
expected:
?- solve(p(X), Result).
X = 1,
Result = [p(1), q(1), t(1), r(1)] ;
X = 2,
Result = [p(2), q(2), t(2), r(2)] ;
X = 12,
Result = [p(12), s(12)].
```

Solution is: 
```Prolog
solve(true, []) :- !. 
solve( (A,B), L) :- !, solve(A, L1), solve(B, L2), append(L1, L2, L).
solve(A, [A | L]) :- clause(A,B), solve(B, L).
```
