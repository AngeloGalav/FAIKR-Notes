# Question 
"The candidate is invited to present the notion of the cut “!” operator in the Prolog
language, shortly explaining how it works. To this end, the candidate is invited to
show a short example of a predicate containing the cut, and to illustrate its effects."

## Answer
The Cut operator essentially stops the backtracking process of some variables, thus making their value selection in the unification and resolution process as definitive.
In practical sense, the evaluation of the cut operator causes the choice points inserted in the backtracking stack to be removed.   
The cut operator is a completely procedural operator, and thus it causes some of the declarativeness of the language to be lost. 
Here's an example of the consequences of this operator:

```Prolog
A)
p(X) :- q(X), r(X).
q(1).
r(2).
q(2).

B)
p(X) :- q(X), !, r(X).
q(1).
r(2).
q(2).
```

In exhibit A, the query ?- p(X) returns true.
In exhibit B, the query ?- p(X) returns false. This is because X is unified with term '1' first, since it is the first value for which q(X) is true. On the other hand,
r(1) is not true, so normally this situation would lead into backtracking. But, the value of q(X) into q(1) is definitive, and as such, backtracking is denied. 
Thus, the query returns false.

## Answer
```Prolog
how_many(A, L) :-
    findall(X,clause(A, X),S),
    length(S, L).
```
