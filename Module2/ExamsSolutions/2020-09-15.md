# Questions
1) The candidate is invited to introduce the meta-predicate clause/2, showing its
use by means of a short example program.

2) The candidate is invited to introduce the Event Calculus framework, discussing its
principles and characteristics from a “bird-eye” perspective.

## Answers

1) The `clause(A,B)` metapredicate returns true if the clause 'A :- B' is present in our database,
meaning that if (A, B) is unified with a clause stored within the database program.

When evaluated:
- A must be instantiated to a non-numeric term 
- B can be a variable or a term describing the body of a clause 

Its evaluation opens choice points, if more clauses with the same head are available. 
Here's a small example:
```Prolog
p(X) :- r(X).
p(X) :- s(X).
r(1).
s(1).
``` 
The query ?- clause(p(X),B) will return 'B=r(X), B=s(X)'. 

2)
The Event Calculus framework is a quantitative time reasoning framework based on points in times, which reifies both fluents and events into terms. 
In particular, _fluents_ are properties whose truth value changes over time, and can be seen as a state state property which can be linked to multiple different events.
The change of value of a state (or fluent) can also be influenced by another fluent.

This formulation comprises an ontology and two distinct set of axioms:
1. Domain-independent axioms (fixed)
2. Domain-dependent axioms (application dependent)

__It is important__, since it allows to represent the state of a system in __logical terms__, in particular FOL.
- It allows to represent and reason on how a _system evolves_ as a consequence of happening events.
- It is an easier formalism (w.r.t. other solutions)

It has various applications, such as Monitoring of systems or Simulating a system’s evolutions. Practically, adopted as a principled framework for representing system evolutions and reactiveness.

It has some limits though:
- Easily implemented in Prolog… but (roughly) not safe if __fluents/events__ contain
__variables__, due to the negation in front of the clipping test (i.e. ¬Clipped( T, F, T ) in the definition of HoldsAt). We can implement that using NAF in Prolog.
- It also allows deductive reasoning only:
    - Takes as input the domain-dependent axioms and the set of happened events…
    - Provides as output the set of fluents that are true after all the specified events.
    - If a new happened event is observed, then a new query is needed: we have to __re-compute from scratch the results…__, which computationally very costly !!!!
