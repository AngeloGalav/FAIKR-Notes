# Question

1) The candidate is invited to report the Prolog vanilla meta-interperter, with a short explanation of the meaning of each clause, and to comment its use in
Prolog programs and knowledge bases.

## Answer

The prolog vanilla interpreter is written as such:
```Prolog
solve(true) :- !.
solve( (A, B) ) :- !, solve(A), solve(B) .
solve(A) :- clause(A, B), solve(B).
```

- The first line is what is evaluated when a clause is true, the cut operator allows to deny the backtracking and assign and make the previous unifications definitive.
- The second line is used for clauses with more than a single predicate, and it simply applies the interpreter to each of the atoms. This clause also allows for a leftmost SLD implementatio, since A is solved first.  
- The third line is probably the most important of the whole interpreter. The `clause` function allows to find a value for B such that there's a clause with A as head, and applies the interpreter to B. 

The meta-interpreter is used in KB to specify new features for the interpreter, and modify other properties. In fact, it allows to essentially change how to interpreter works, for example by modifying the SLD resolution process (i.e. making rightmost).   

It can also be used to implement an expert system. 

# Question
2) The candidate is invited to Forward reasoning in rule-based systems, and to highline the difference w.r.t. backward reasoning.

## Answer
The Event Calculus framework is a quantitative time reasoning framework based on points in times, which reifies both fluents and events into terms. 
In particular, _fluents_ are properties whose truth value changes over time, and can be seen as a state state property which can be linked to multiple different events.
The change of value of a state (or fluent) can also be influenced by another fluent.
The main characteristic of this type of framework is the use of a Working Memory, which is a data structure that allows for new facts to be added dynamically to the Knowledge base, without having to restart reasoning from scratch. 

This idea is also the main difference w.r.t. backward reasoning, i.e. Prolog. Even though in this language we can use the assert() function in order to add another rule to the KB, it results in losing the declariteveness of the program, and could result in strange behaviours. So usually what it is done is _restarting reasoning from scratch after adding the fact_.  
Also, in backward reasoning, we also start from the consequence of a rule (head) and from that we try to evaluate if the body is true.
