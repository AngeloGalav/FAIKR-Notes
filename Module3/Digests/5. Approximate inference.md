## Inference by stochastic simulation
Basic idea:
1. Draw $N$ _samples_ from a sampling distribution $S$
2. Compute an _approximate_ posterior probability $\hat P$ 
3. Show that this probability converges to the _true probability_ $P$
So, it's an _approximation_ :). 

There are many methods for exact inference:
- Sampling from an empty network 
- Rejection sampling: reject samples disagreeing with evidence 
- Likelihood weighting: use evidence to weight samples 
- Markov chain Monte Carlo (MCMC): sample from a stochastic process whose stationary distribution is the true posterior

## Performance of approximation algorithms
Absolute approximation: $: |P(X|e) - \hat P(X|e)|\le \epsilon$
Relative approximation: $\dfrac{|P(X|e) - \hat P(X|e)|}{P(X|e)}\le \epsilon$

The approximation gets closer to the real value the more we draw samples from N, but also the complexity of the algorithm increases.   

>[!Theorem]
>Both absolute and relative approximation for either deterministic or randomized algorithms are _NP-hard_ for any $\epsilon, \delta < 0.5$.

## Sampling from an empty network 
This is the simplest method of the one listed before. 

```JS
function PriorSample(bn) returns an event sampled from bn 
inputs: bn, a belief network specifying joint distribution P(X1,..., Xn) 
	
	x <- an event with n elements 
	for i = 1 to n do 
		xi <- a random sample from P(Xi|parents(Xi))
		given the values of Parents(Xi) in x 
	
	return x
```

Idea: sample each variable in turn, in _topological order_ (of the Bayes network, meaning from the parents to the children). 

Essentially, we draw 4 random numbers in \[0, 1\] (for 4 nodes/variables of a Bayesian net). We assign to each variable, and through that we've made a sample woohooo. 

Probability that $PriorSample$ generates a particular event.
$S_{PS}(x_1 ... x_n) = \sum^n_{i = 1} P(x_i|parents(X_i)) = P(x_1 ... x_n)$

i.e. $S_{PS} (t, f ,t,t)=0.5 \cdot 0.9 \cdot 0.8 \cdot 0.9=0.324 = P(t, f ,t,t)$
Let $N_{PS} (x_1 ... x_n)$ be the _number of samples_ generated for event $x_1,..., x_n$
Then we have:
![[lim_sampling.png]]

That is, estimates derived from $PriorSample$ are _consistent_.
Shorthand: $\hat P(x_1,..., x_n) \approx P(x_1 ... x_n)$.

The problem is that this method needs a lot of samples. 

## Rejection sampling 
It's an extension of empty network sampling, but essentially you are defining evidence in a way. 

You can do that by fixing the evidence in a network, and you do that by generating samples and _discard samples_ that are in _contrast_ with your evidence.

```JS
function RejectionSampling(X,e,bn,N) returns an estimate of P(X|e)
local variables: N, a vector of counts over X, initially zero 
	
	for j = 1 to N do 
	x <- PriorSample(bn) 
	if x is consistent with e then 
		N[x] <- N[x]+1 where x is the value of X in x
	 
	 return Normalize(N)
```

E.g., estimate $P(Rain|Sprinkler = true)$ using 100 samples 
- 27 samples have $Sprinkler = true$ 
- Of these, 8 have $Rain = true$ and 19 have $Rain = false$. 
- $\hat P(Rain|Sprinkler = true) = Normalize(<8, 19>) = <0.296, 0.704>$ 
- Similar to a basic real-world empirical estimation procedure

## Likelihood weighting
Idea: fix evidence variables, _sample only non-evidence variables_ and _weight each sample_ by the likelihood it accords the evidence.
```JS
function LikelihoodWeighting(X,e,bn,N) returns an estimate of P(X|e) 
local variables: W, a vector of weighted counts over X, initially zero 
	
	for j = 1 to N do 
		x,w <- WeightedSample(bn,e) 
		W[x] <- W[x] + w where x is the value of X in x 
	return Normalize(W[X])
```

```JS
function WeightedSample(bn,e) returns an event and a weight 
	
	x <- an event with n elements initialized from e
	w <- 1 
	for i = 1 to n do 
		if Xi is an evidence variable with value xi in e then
			w <- w * P(Xi = xi|parents(Xi )) 
		else xi <- a random sample from P(Xi|parents(Xi )) 
	return x, w
```

#### Analysis of likelihood weighting
Sampling probability for $WeightedSample$ is $S_{WS}(z, e) = \prod^l_{i=1} P(z_i|parents(Z_i))$.
Weight for a given sample z, e is $w(z, e) = \prod^m_{ i = 1} P(e_i|parents(E_i))$ (Notice, we are using the evidence instead of the other variables). 

So, the weighted  sampling probability is:
$S_{WS}(z, e) w(z, e) = \prod^l_{i=1} P(z_i|parents(Z_i)) \prod^m_{ i = 1} P(e_i|parents(E_i)) = P(z,e)$ 
Hence likelihood weighting returns _consistent estimates_, but performance still degrades with many evidence variables because a few samples have nearly all the total weight (and the final estimate is _dominated_ by such samples).
- Essentially, we may generate samples with very little weight. 
- So, again, the best thing to do is to have a lot of samples. 

## Markov-chain Monte Carlo 
With $Sprinkler = true$, $WetGrass = true$, there are four states:
![[markov_chain_example.png]]
Essentially, we determine the connections between graphs in which the distance of "difference" is determined by only one variable. 

##### Example
Given the graph above, we need to estimate $P(Rain | Sprinkler  = true, WetGrass  = true)$.
What we do is that:
- we sample $Cloudy$ or $Rain$ given its Markov blanket, and then repeat. 
- Count the number of times $Rain$ is _true_ and _false_ in the samples.

E.g., we visit 100 states, 31 have Rain = true, 69 have Rain = false, then:
$\hat P(Rain|Sprinkler = true, WetGrass = true) = Normalize(<31, 69>) = <0.31, 0.69>$

### Stationary distribution
We generate samples that reflect the true distribution by reaching something called the "stationary distribution":
>[!Definition]
>_stationary distribution_: is a distribution where fraction of time spent in each state is exactly proportional to its posterior probability. 

```JS
function MCMCAsk(X,e,bn,N) returns an estimate of P(X|e)
local variables: N, a vector of counts for each value of X, initially zero 
				 Z, the nonevidence variables in bn 
				 x, the current state of the network, initially copied from e 
				 
	 initialize x with random values for the variables in Z 
	 for j = 1 to N do
		for each Zi in Z do 
			set the value of Zi in x by sampling from P(Zi|mb(Zi))
			N[x] <- N[x] + 1 where x is the value of X in x 
	
	return Normalize(N)
```

#### Markov blanket sampling example
Markov blanket of $Cloudy$ is ... $Sprinkler$, $Rain$
Markov blanket of $Rain$ is ... $Cloudy$, $Sprinkler$ and $WetGrass$

Probability given the Markov blanket is calculated as follows:
$P(x_i' |mb(X_i)) = P(x'_i |parents(X_i)) \prod_{Z_j \in Children(X_i)} P(z_j |parents(Z_j))$

Main computational problems: 
1. Difficult to tell if convergence has been achieved 
2. Can be wasteful if Markov blanket is large: $P(X_i|mb(X_i))$ won’t change much (law of large numbers)

### Compiling approximate inference 
The problem of approximate inference is that it can only be applied on graphs such that you can walk through each node. If a node of the graph is not "walkable"/connected to the rest of the graph, then it is not representative of the real world.
- So, you must make sure that the whole graph is _reachable_.
- So, this method does not work with _deterministic probabilities_, in which the probability of reaching a node from another could be zero.
