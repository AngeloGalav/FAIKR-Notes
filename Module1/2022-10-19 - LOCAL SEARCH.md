# A* in Graph search

This is general algorithm for searching a graph:
```
function Graph-Search (problem, fringe)
	closed = empty
	fringe = Insert(MakeNode(InitialState[problem]), fringe)

	while true:
		if fringe is empty then 
			return fail
		
		node = RemoveFront(fringe)
		
		if Goal-Test[problem](State[node])
			return Solution(node)
		
		if State[node] is not closed 
			add State[node] to closed
			fringe = InsertAll(Expand(node, problem), fringe)
```

When we use A* in a graph, we have __two lists__:
- _closed nodes_: expanded nodes, which are removed from hte list to avoid further examination. 
- _open nodes_: nodes that still have to be examined.

Since we are searching a graph instead of a tree, the only differences are that:
- The graph can become a tree with repeated nodes
- Add the list of closed nodes and assum that $g(n)$ evaluates the minimum distance of node $n$ from the starting node. 


### Consistent heurisitic in A*

A further condition of the function $h$ is consistency (_coerenza_). 
> [!DEFINITION]
> A heuristic is __consistent__ if for each node $n$, any successor $n’$ of $n$ generated by each action $a$:
> $h(n) = 0$ if the corresponding status is the goal
> $h(n) \le c (n, a, n') + h(n')$ otherwise

This condition ==guarantees us to find the shortest path== from the root to the goal, and makes A* optimal. 

In fact, thanks to consistency, we have that:
$$\begin{align}
f(n') &= G(n') + h(n') \\
& = G(n) + c(n,a,n') + h(n') \\
& \ge g(n) + h(n) \\
& = f(n)
\end{align}$$
This way, $f(n)$ never decreases along a path.

# Local Search

The constructive algorithms (seen so far) generate a solution by adding _components_ to a starting (empty or initial) state solution in a particular order. 
Local search algorithms start from an <span style="color:yellow">initial solution</span> and ==iteratively try to improve it through local moves.== Local moves define a __neighborhood__. 

This tecnhique is applicable when the path to reach a goal/solution is not important: that is, when the problems (for example, the n queens problem) have the property that the state description contains all the information necessary for understanding if __one configuration is a solution or not__ (the path is irrelevant). 

In this case local search algorithms often provide a valid alternative. For example, we can start with all the queens on the board and then move them to reduce the number of attacks.

Local search is very fast, and takes little space. 

### N queens problem
We have a $n \cdot n$ chessboard, and we have to put $n$ queens in it, such that they mustn't attack each other. 

The 1st solution consists in putting the queens randomly. After that, we can move each queen that is attacked. These are __local moves__: I'm changing the state in the hope that the solution becomes feasable. 

We have what is called a __fitness function__, which essentially determinates how much a state is close to the optimal state. Determing this function is one of the tasks that we have to complete.  

![[chess.png]]
For example, in this image the 1st is further from the optimal state than the 2nd. 

How to construct the solution in this problem? We have to make a couple of strides:
1. We start from state 0: and empty board.
2. We position the queens (randomly)
3. You select each attacked queen an position it in a "safe" place. 

### Neighboorhood

>[!Definition of Neighborhood] 
>$N : S \longrightarrow 2^S$
>Assigns to every $s \in S$ a set of neighbors $N(s) \subseteq S$.  $N(s)$ is called the neighborhood of $s$.

A neighbourhood is a function that goes from a set to the _powerset_ (insieme delle parti) of S. 
Just for reference:
- $S$ is the set of states, and could be seen as the search space.
- $s$ is a single state. 
- $2^S$ is the powerset of $S$. 
This definition is exactly what it seems at first glance. 

### TSP 
Given an undirected graph, with $n$ nodes and each arc associated with a positive value, find the Hamiltonian tour with the __minimum total cost__.

This problem can be solved through <span style="color:red">local search</span>: we select a cycle at random which passes through each node, and then we "correct" any path or segment that can be optimized. 
We iterate through the graph each time until we have a solution. 

As Asperti said, this is an $NP-complete$ problem and is very difficult to solve. 

One of the local search techniques that can be used to solve the problem consists in the <span style="color:limegreen"><b>K-exchange</b></span>.
In this technique, a solution is represented by a permutation of numbers which represent the nodes of the path in succession, and if I take 2 cities and swap them, then I'm basically just changing the tour. 

Some of the k-exchange strategies include:
- 2-swap: swap two numbers in a sequence. 
- k-cycle: select k positions and cycle on their numbers
	i.e. $(1, 2, 3, 4, 5, 6, 7, 8) → (1, 5, 3, 2, 4, 6, 7, 8)$

Sometimes, the paths returned using these methods are unfeasible, and must be ignored. 

## Hill Climbing Algorithm (Iterative Improvement)
This is the most used local search algorithm. 
Essentially, you choose a move only if ==it improves the solution== (that is, the solution produced is better than the current one).
The algorithm stops only if it finds a __local minimum__: so I explore a neighbor and I stop if the neighborhood does not contain a better solution. 

==This does __not__ guarantee to find an absolute optimal solution==.  

There are many, many variants of this algorithm. 

The algorithm is extremely simple: you just generate a solution, create the neighbors and evaluate if it can be improved through its neighbors.

The algorithm for iterative improvement can be written as:
```
s ← GenerateInitialSolution() 
repeat 
	s ← BestOf(s, N(s)) 
until no improvement is possible
```

##### Drawbacks
The main drawbacks of this algorithm are that:
- it's not effective in exploring the search space (e.g., it stops at the first local optimum encountered).
- Does not remember the search states already reached.

## Definition of _Local Optima_
A <span style="color:red">local maximum</span> is a solution $s$ such that for any $s'$ belonging to $N(s)$, given an evaluation function $f$, we have that:
$$
f(s) \ge f(s')
$$
When we solve a _maximization_ problem, we look for a __global maximum__ $s_{opt}$  such that 
for __any__ $s$,$$
f(s_{opt}) \ge f(s)
$$We have an analogous consideration for the minimum (with inverted sign obviously).

The larger the neighborhood, the more likely a local maximum is a global maximum (but obviously there is a problem of computational effort). So, the larger neighborhood, the higher the quality of the solution.

### Other problems
- Local Optima: states that are better than all the neighbors, but _worse_ than other states that are not nearby.
- __Plateau__: flat areas of the landscape in which ==neighboring states have the same value==. It is very difficult to chose in which direction to move (random choice?). 
- __Ridges__ (trad. angolo, cresta): it is a higher area adjacent to those where we should go, but we can not go there directly. So we need to move in another direction to get there. Essentially, these are places that are not directly reachable.  

# Meta Heuristic

==Local Search has many pitfalls, and some more effective solutions are required==. 
The main pitfall is that, while it is very fast, it gets stuck on _local moves_. 
In general there are three techniques to improve local search:

- <span style="color:limegreen"><b>Accepting non-improving moves</b></span>: basically when you are in a local optima, if you accept worse moves you can maybe accept another "hill" to climb that you couldn't reach before. 

- <span style="color:limegreen"><b>Change neighbourhood or cost function during search</b></span>: essentially, when we find a local optima, we check another neighborhood so that we are more likely to find something better. 

- Using <span style="color:limegreen"><b>high level search strategies</b></span>: i.e. tablut search. These strategies kinda provide some long term memory.
