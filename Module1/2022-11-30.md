# Graph planning
It is a very efficient way of planning. It is based on a planning graph, which contains all the available plan in a certain situation (?) . Once this graph is created, you search the optimal plan backward.

It takes in consideration the notion of time, but not as a duration (like a scheduler), but in this way: ==it positions in TIME various actions==. 

It is a correct and complete planner among the most efficient that have been built. 

This plan also guarantees that each plan found is the shortest possible plan. Graphplan uses the _CLOSED WORLD ASSUMPTION_, and thus falls into the category of off-line planners.

Graphplan inherits from non-linear partial order planners the ability to create partially ordered sets of actions: it generates parallel plans (plans that can be executed in parallel).

### Inconsistent actions
Inconsistent effects: one action negates the effect of another – The move action (part, dest) has the effect not at (part) while the no-op action on at (part) has this effect 
- action-action
- o p
- o ¬p
- Interference: an action deletes a precondition of the other – The move action (part, dest) has the effect not at (part) while the no-op action on at (part) has this as a preconditions 
- preconditions -action
	- o ¬p 
	- p o
- Competing needs: two actions that have mutually exclusive preconditions. 
	- The load share (load means) has as a precondition not in (load means) while the action unload (load means) has as a precondition for (load means)
	- preconditions -precodition
	- ¬p o

### INCONSISTENT PROPOSITIONS
Two propositions are inconsistent if 
- one is the negation of the other 
- If all the ways to reach them are mutually exclusive 

Furthermore, there might be domain dependent inconsistencies. (i.e. an object cannot be in two places at the same time in the same time step)

### Example 
Consider that we have a cart $R$ and two loads $A$ and $B$ that are in the starting position $L$ and must be moved to the target position $P$.

We have 3 available actions:
- Move(R, PosA, PosB)
	- PRECONDIZIONI: at(R,PosA), div(PosA, PosB), hasFuel(R) 
	- ADD LIST: at(R,PosB) 
	- DELETE LIST: at(R,PosA), hasFuel(R)
	
- Load(Pos, Object)
	- PRECONDIZIONI: at(R,Pos), at(Object,Pos) 
	- ADD LIST: in(R, Object) 
	- DELETE LIST: at(Object,Pos)

- Unload(Pos, Object)
	- PRECONDIZIONI: in(R, Object), at(R,Pos) 
	- ADD LIST: at(Object,Pos) 
	- DELETE LIST: in(R, Object)

Once we have built the graph (which means, building a graph with the goal conditions in the last layer), we now have to extract a __valid-plan__, which is a connected and consistent subgraph of the planning graph. 

To do that, we proceed backwards from the last layer. 

Some theorems that help us find a valid plan:
1. If there is a valid plan then this is a subgraph of the planning graph. 
2. In a planning graph, two actions are mutually exclusive in a time step if a <u>valid plan that contains both does not exist</u>. 
3. In a planning graph two propositions are mutually exclusive in a time step if they are inconsistent, i.e. one of them denies the occurrence of the other!
